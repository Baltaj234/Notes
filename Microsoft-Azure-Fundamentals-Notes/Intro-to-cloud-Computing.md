In this module you are introduce to general cloud computing concepts. An introduction to cloud in general. Intermediate concepts like shared responsibility, different cloud modeles and unique pricing for the cloud.

# What is Cloud Computing?
In a simple sense: It is the delivery of services over the internet.
Common IT Infrastructure includes virtual machines, storage devices, databases and networking.

Because cloud computing uses the internet to deliver services, it is not constrained by the physical infrastructure the same way a datacenter is.

Cloud can be used to rapidly expand your IT footprint.

# Share Responsibility Model
Responsibilites are shared with the cloud provider and consumer. 

Physical security, power, cooling, and network connectivity are the responsibility of the cloud provider. 

Consumer is responsible for the data and information stored in the cloud. Also, for access security (meaning you can only give access to those who need it). 

Note: Responsibility can also depend on the exact technical details too. 

With an on-premise datacenter, you are responsible for everything. 

# Responsibility by service model

Platform as a Service
Software as a service
Infastructure as as service

Cloud provider users are always accountable for the info and data stored on the cloud, devices that are allowed to connect to the cloud and the accounts associated with the cloud.

The actual cloud provider is responsible for the physical datacenter, the physical network, the physical hosts and infrastructure.

The service model will determine responsiblity for things like Operating Systems, Network Controls, Applications and Identity/Access.

# Defining Cloud Models

Private Cloud:

Used by a single entity. Provides much greater control for your IT team. 

Comes with greater cost and fewer benefits of a public cloud deployment. May be hosted from your on-site datacenter or in a dedicated datacenter offsite.

Public Cloud:

Built, controlled and maintained by a third party cloud provider. 

Anyone can purchase access to cloud services/resources. It has public availability.

Hybrid Cloud:

Uses both public and private clouds in an inter-connected environment. 

Can be a provider of extra layers of security. Users can choose with services to keep public and which to keep private.

MultiCloud:

The act of using multiple cloud providers. Maybe you want to use a mix of different features from different providers.

Deal with two (or more) public cloud providers to manage resources and security in both environments.

Azure Arc:

Set of technologies that help manage your cloud environment. 

Azure VMware Solution:

Lets you run your VMware workloads in Azure with seamless integration and scalability.

# The Consumption Based Model

Paying for the IT resources you use and nothing more. You are essentially renting power and storage. 

Then releasing those resources when you're done. 

Benefits include no upfront costs for hardware, no purchasing capacity that may go un-used, the ability to add resources as demand increases and the ability to release resources when demand decreases.

# Cloud Pricing

Most cloud providers use a pay as you go pricing model. You typically pay only for the services you consume. 

# Benefits of high availability in the cloud

High availability focuses on ensuring maximum availability, regardless of disruptions that might occurr.

Scalablity of cloud services is another benefit. Scalablity can adjust cloud resources to meet a certain type of demand at any given time.

Vertical Scaling is focused on increasing/decreasing resource use.

Horizontal Scaling is focused on adding/subtracting the number of resources.

Examples of vertical scaling include more processing power, CPU, Ram, etc.

Examples of horozontal scaling include additional virtual machines, more deployed resources, etc.

# Reliablity and predictability in the cloud

Reliability is the system's ability to recover from failures, then continue to function. The cloud naturally supports a reliable and resilient infrastructure. 

Predictability in the cloud lets you move forward with confidence. It can be focused on performance or cost.

Performance predictability focuses on predicting the resources needed to deliver a positive experience for your customers. 

Cost predictability is focused on predicting or forecasting the cost of cloud spend. With the cloud, you can track your resource use in real time and monitor resources to ensure your using them in the most efficient way.

# Security and governance in the cloud

Tools such as templates help ensure the deployed resources meet your technical standards and regulatory requirements. As standards change, you can update your resources at scale.

For max security control, infrastructure as a service provides you with physical resources but lets you manage the operating systems and installed software.

If you want patches and maintence to be taken care of automatically, then software as a service deployments is a better strategy for you.

# Manageability in the cloud

In the cloud you can:

Automatically scale resource deployment based on need

Deploy resources based on a preconfigured template

Monitor health of resources and automatically replace failing resources

Receive automatic alerts based on configured metrics, so you're aware of performance in real time.

Management in the cloud speaks to how you're able to manage your cloud environment and resources. 

You can manage these:
Through a web portal
Using a command line interface
Using API's
Using Powershell

# Sustainability Considerations in the cloud

Cloud computing can support sustaiability goals when teams actively organize how resources are deployed and used.

Examples of practices that support sustainability and cost efficiency include:

Scaling resources down when demand decreases
turning off or deallocating resources that are not in use
Choosing efficient services and configurations to reduce overprovisioning
Using governance and monitoring to track usage trends and optomize deployments over time

At a foundational level sustainability in the cloud is tied to good operational habits. Right-size, automate, monitor, and continuously optomize.
